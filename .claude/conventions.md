# Conventions

Repository-wide conventions. Module-level rules live beside the code: `platform-sdk/CLAUDE.md` for the consensus layer's module categories and dependency rules, each module's own `CLAUDE.md` or `README.md`, and `docs/hedera-java-style-guide.md` for Java style.

- **Deterministic by construction.** Code on the transaction-handling, state or consensus path produces the same result on every node: no wall-clock time (use consensus time), no iteration over unordered collections, no dependence on thread scheduling, floating point, locale or unseeded randomness. A test that would catch a divergence belongs in the same pull request.
- **Compatible by construction.** Protobuf fields are added, never renumbered, retyped or repurposed; a state schema change comes with its migration from the previous release; a stream format change stays readable by the tools that consume it (mirror node, block node).
- **License headers.** The project is Apache 2.0. Every source, build and config file starts with `SPDX-License-Identifier: Apache-2.0` in that file's comment syntax (`//` in Java and Kotlin, `#` in YAML, shell, Python and `.properties`); copy it from a neighboring file. `./gradlew spotlessApply` adds it to Java, Kotlin, `.github/` YAML and `.properties` files. Never add a different license or a copyright line.
- **Java.** Format with Spotless (Palantir Java format) and follow `docs/hedera-java-style-guide.md`. Every module is a JPMS module: export only API packages, keep `internal` packages internal, and `requires` only what the module uses (`checkAllModuleInfo` fails otherwise). Every external version lives in `hiero-dependency-versions/`. Javadoc every public type and member.
- **Markdown Javadoc in new code.** Write Javadoc for new types and members as Markdown documentation comments (`///`, JEP 467): Markdown lists, `` `code` `` and `[Type#member]` links instead of `<p>`, `<ul>`, `{@code}` and `{@link}`. Section 7 of `docs/hedera-java-style-guide.md` still applies apart from its HTML formatting (summary fragment, block tag order, where Javadoc is required). When editing an existing `/** */` comment, keep that file's style rather than converting it in passing.
- **Tests at the lowest level that reaches the code.** Unit tests first; then integration, HAPI or Otter tests for what unit tests cannot reach. A test must not be flaky: no arbitrary sleeps or timeouts. A pull request that changes a test's expected values says why.
- **American English in prose.** Documentation, comments, commit messages, and PR and issue text use American spellings: `behavior`, `color`, `license`, `-ize`. Identifiers and external names are exempt.
- **GitHub Actions.** Every external action is pinned by full SHA with a `# vX.Y.Z` trailing comment; Dependabot keeps the SHAs fresh. File and workflow names follow `.github/workflows/docs/naming-standards.md` (`ddd-xxxx-<name>.yaml`, `name: "ddd: [XXXX] <Name>"`), and `.github/workflows/docs/workflow-manifest.md` lists every workflow. Workflow boilerplate: the `# SPDX-License-Identifier: Apache-2.0` header, `defaults.run.shell: bash`, explicit least-privilege `permissions:` (escalate per job), `runs-on:` an `hl-cn-*` runner, and `step-security/harden-runner` as the first step of every new job. Never check out or run pull request code in a `pull_request_target` workflow, and never interpolate `${{ github.event.* }}` text straight into a `run:` script: pass it through `env:`.
- **Conventional Commits, everywhere.** PR titles match Conventional Commits (`type(scope): short description`), enforced by the Title Check in `601-flow-pull-request-formatting.yaml`; commit subjects follow the same style, checked locally by the `conventional-pre-commit` hook in `.pre-commit-config.yaml`. Many titles carry the issue number after the type (`ci: 28318: Make every dry-run input a boolean`). Squash-merge is the default, so the PR title becomes the commit on `main`. Subjects are imperative, at most 72 characters, with no trailing period.
- **Every PR has a backing issue, an assignee, and closes the issue.** The PR body's first line is `Fixes #N` (or `Closes #N`) for each issue it resolves; if no issue exists, create one first, describing the problem in its own terms. The Assignee Check fails a PR without an assignee. Set the milestone when the maintainers ask for one.
- **Branch naming.** `<issue_number>-<short-description>` in kebab-case, the description at most 20 characters, no slashes (`docs/branch-naming-conventions.md`). Start from a freshly pulled `main`.
- **Stacked PRs are real `gh stack` stacks.** A chain of dependent pull requests is created with the `gh stack` extension (`gh stack init` / `gh stack submit`, or `gh stack link` for PRs already open), not with a hand-set `--base`. See the `gh-stack-workflow` skill.
- **Sign every commit, two ways.** Commits are (1) GPG-signed (`git commit -S`, with Vigilant Mode on in GitHub) and (2) carry a DCO `Signed-off-by:` trailer matching the author (`git commit -s`, or the `prepare-commit-msg` hook in `.claude/git-hooks.md`); the DCO check rejects a PR otherwise (`docs/maintainers-guide.md`). Never bypass either with `--no-gpg-sign` or `--no-verify`.
- **Amend rather than pile up.** Before adding a commit, check whether the change belongs to an existing unpushed commit (`git log --oneline origin/main..HEAD`) and `git commit --amend -sS --no-edit` into it if so.
- **Review in new commits.** Address review feedback in additional commits; don't force-push a branch under review unless asked (a `gh stack` rebase is the exception).
- **CODEOWNERS in two files.** An ownership change edits `.codeowners` and `.github/CODEOWNERS` together, and a new module gets an entry in both.
- **Never attribute work to the agent.** No "Generated with Claude Code", no `Co-Authored-By: Claude`, no similar marker, anywhere in the repository or its history.
- **Security issues are reported privately**, as described in the [Hiero security policy](https://github.com/hiero-ledger/.github/blob/main/SECURITY.md), never in a public issue or pull request.
