# TSS startup assets

This directory holds committed warm-start fixtures for the CLPR multi-network HAPI tests.
WRAPS proving parameters are bundled in the 3.23.0 library; no artifact download or environment
variable is needed. These fixtures retain the compatible Nova proofs generated after the 3.18.0
migration; pre-3.18.0 proofs cannot be reused.

## Fixture naming

There is **one fixture per network**, regardless of size, named
`<network>-genesis-network.json.gz` (e.g. `ledgerA_manifest-genesis-network.json.gz`).

### Digest-type variants

Fixtures are namespaced by the digest the network was captured under, selected by
`Cryptography.DEFAULT_DIGEST_TYPE` (`TssFixtures` reads it before any node forks):

- **SHA-384 (current):** bare name, e.g. `ledgerA-genesis-network.json.gz`.
- **SHA-256:** `-sha256-` infix, e.g. `ledgerA-sha256-genesis-network.json.gz`.

The SHA-256 fixtures from `main` used pre-3.18.0 WRAPS proofs and are not included here.
Until compatible fixtures are regenerated with this branch's library, SHA-256 runs bootstrap
fresh. The retired `wrapsProvingKeyHash` is not used by the bundled-parameter WRAPS library;
its old length does not describe the current 64-byte ledger ID.

Both loading (`resolveCachedFixturePath`) and regeneration (`generateNetworkFixture`) flow through
`TssFixtures.fixtureFileName`, so the active digest picks the right variant automatically. The
port-reservation scan (`fixtureNetworkName`) is digest-aware too: it only sees the active digest's
fixtures, so the inactive set never shadows a network's reserved ports. A SHA-256 fixture can only be
**generated** on a build whose `DEFAULT_DIGEST_TYPE` is `SHA_256`; until that set is produced, SHA-256
runs find no fixture and take the cold path.

A `genesis-network.json` carries each node's TSS private key in `nodeTssMetadata`, and a node
can only export *its own* secret. So on export the per-node freeze exports are **merged** into one
file whose `nodeTssMetadata` holds every node's private-key entry (see
`TssFixtures.mergeNodeExports`). One file warm-starts the whole network because at
genesis `TssStartupNetworks` loads only the self node's key (filtered by `selfNodeId`) into
node-local key files, and the public material that enters hashed state is identical for every node.

The mapping is `TssFixtures.fixtureFileName(networkName)`.

## Expected contents

```
tss-startup-assets/
├── README.md                                       (tracked)
├── ledgerA-genesis-network.json.gz                 (tracked)
├── ledgerB-genesis-network.json.gz                 (tracked)
├── ledgerA_mtls-genesis-network.json.gz            (tracked; mTLS suite)
├── ledgerB_mtls-genesis-network.json.gz            (tracked; mTLS suite)
├── ledgerA_manifest-genesis-network.json.gz        (tracked; size-2 manifest suite, merged)
├── ledgerB_manifest-genesis-network.json.gz        (tracked; manifest suite)
├── ledgerA_restart-genesis-network.json.gz         (tracked; restart suite)
├── ledgerB_restart-genesis-network.json.gz         (tracked; restart suite)
└── <network>-genesis-network.json                  (gitignored; optional local copies)
```

`TssFixtures.resolveCachedFixturePath` prefers the `.gz` form when both exist, so a
stale uncompressed local copy can never silently shadow the committed source-of-truth.

## Warm-cache fixtures — committed in gzipped form

The `*-genesis-network.json.gz` files in this directory are committed to git.
On CI and on any fresh clone, `@MultiNetworkHapiTest.Network(tssPreload = true)`
tests find them automatically and skip the WRAPS bootstrap. No manual
seeding required.

The install path, per node, before the subprocess JVM starts:

1. `TssFixtures.installFixture` gunzips the merged fixture into the
   subprocess node's `data/config/genesis-network.json` (the form
   `DiskStartupNetworks` reads).
2. The loader reserves capture-time ports when possible. If another fixture owns those ports,
   it allocates a free range and patches the installed fixture's transport endpoints and construction
   roster references. Keys, weights, and proofs remain unchanged: WRAPS binds the address book's
   cryptographic identities and weights, not its transport ports.

### Running a suite directly

A direct `testSubprocess --tests` run bypasses task-specific CLPR defaults. Use
`-PsysProp.hapi.spec.test.overrides=tss.forceMockSignatures=false,clpr.enabled=true,hedera.transaction.maxBytes=16384`.
Real signatures are required for WRAPS-bearing blocks; CLPR must be enabled; the enlarged transaction limit
allows the suites' direct `verifyConfig` calls carrying a roughly 15 KB state proof.

### Regenerating

All fixtures are (re)generated by `ClprFixtureGeneratorSuite` (`@Tag(MULTINETWORK)`,
`@Disabled("Fixture generator")`), one test per fixture set:

- `generateLedgerFixtures` -> `ledgerA`, `ledgerB`
- `generateRestartLedgerFixtures` -> `ledgerA_restart`, `ledgerB_restart`
- `generateMtlsLedgerFixtures` -> `ledgerA_mtls`, `ledgerB_mtls`
- `generateManifestLedgerFixtures` -> `ledgerA_manifest` (size 2), `ledgerB_manifest`

Each brings its network(s) up cold (only when the committed fixture is deleted); the
`@MultiNetworkHapiTest` extension then freezes, merges each node's freeze export into one
`<network>-genesis-network.json.gz`, and restarts warm. The suite is `@Disabled` so it never
runs in a normal suite pass. Remove that `@Disabled` to run it (deactivating the condition with
`junit.jupiter.conditions.deactivate` does not work: the multi-network listener never starts the
networks of `@Disabled` tests).

**To regenerate one fixture set:**

1. Delete its committed fixture(s), e.g.:

   ```bash
   rm ledgerA_manifest-genesis-network.json.gz ledgerB_manifest-genesis-network.json.gz
   ```
2. Remove the `@Disabled` from `ClprFixtureGeneratorSuite` and run its generator:

   ```bash
   ./gradlew :test-clients:testSubprocess \
     --tests "*ClprFixtureGeneratorSuite.generateManifestLedgerFixtures" \
     "-PsysProp.hapi.spec.test.overrides=tss.forceMockSignatures=false,clpr.enabled=true,hedera.transaction.maxBytes=16384"
   ```
3. Restore the `@Disabled` and `git add` the regenerated `*-genesis-network.json.gz`.

**To regenerate everything with coordinated ports**, delete all the committed
`*-genesis-network.json.gz`, remove the suite's `@Disabled`, and run the whole suite in one JVM, so
`ensureFixturePortReservations` gives each network a globally-unique, non-overlapping port range
that its warm consumers then reproduce:

```bash
rm *-genesis-network.json.gz
./gradlew :test-clients:testSubprocess --tests "*ClprFixtureGeneratorSuite" \
  "-PsysProp.hapi.spec.test.overrides=tss.forceMockSignatures=false,clpr.enabled=true,hedera.transaction.maxBytes=16384"
```

Restore the `@Disabled` afterwards. `TssFixtures.generateNetworkFixture` writes each fixture directly as
`<network>-genesis-network.json.gz` (no manual `gzip` step); `git add` them as-is.
